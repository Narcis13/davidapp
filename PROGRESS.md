## Decisions

- **The machine.** The brief describes macOS 15.5 on an Intel i5 with FFmpeg 8.1 and 5.5 GB free; this session runs on the Windows 11 PC (i9-14900KF, 32 threads, 1.7 TB free, Node 24.19, FFmpeg 9.0.2). Baselines (hashes, speed) are taken here, from a worktree of `4a394de` that shares this checkout's `node_modules`. FFmpeg 9 here has `drawtext`, libass and a `whisper` filter; the studio does not use them (the Macs' builds lack them): times on sheets are drawn with Skia, captions are drawn by assets, and whisper.cpp is a separate program.
- **Narration = a sound asset with words** (`meta.narration = { script, words, extra, language, source, voice, take }`), not a new asset type: an audio track takes it as it takes any sound, search and lineage work unchanged, and no CHECK-constraint migration is needed. A new take of the same script is a **new version of the same asset** (versions stay immutable; clips pin them; `repin_clip` moves a clip to the new take). Words are the script's words in order, so word *i* means the same word in every take: imported timings (whatever service or aligner made them) are aligned to the script by a Levenshtein alignment over normalised tokens; a script word the take dropped gets a time interpolated from its neighbours and `missing: true`; words the take added are kept in `extra`. Word anchors refer to `{ item, word: i }` (the narration item on the clip and the script word index), so they survive a new take.
- **Word anchors are resolved when the clip is saved** (`clips.prepare`, which already pins every reference): an item `anchor: { item, word, edge: start|end, offset }` sets `start`; a keyframe `{ t, v, ease, anchor }` sets `t`; a marker `{ type: 'word', anchor }` sets `t`. The composition stores both the anchor and the resolved time, so the runtime (Node and the preview) stays a pure function of the composition, and every save (including a repin to a new take) re-resolves. `anchor_report` gives each anchored thing's distance to its word in frames.
- **Captions are structure in the composition, times from the words.** `composition.captions = { from, maxLines, maxChars, lead, minDuration, closeGap, burnIn, names, pages }`: `pages` (optional) lists each page's first word and line break as word keys (`"<item>:<i>"`); without it the pages come from the rules. Times are computed from the words every time, so edits (move a break, merge, split) never carry a time of their own. Pages reach assets as `f.clip.captions` and the lane as `f.clip.lane`. A track with `role: 'captions'` is not drawn when `burnIn` is false (file only).
- **The mix moves from FFmpeg's filter graph to a JS mixer** (`src/render/mix.js`): sources are decoded once by FFmpeg to 48 kHz stereo float (cached, bounded), then placed, trimmed, faded, gained (linear `gain` × `keyframes.volume` in dB) and ducked per sample. One function makes the WAV the preview plays and the WAV the render encodes, so they are the same samples (tested by hash). Audio easing curves are built in (`linear`, `hold`, `smooth`, `in/out/inOut` × `Sine/Quad/Cubic`) rather than read from the easing asset: no asset code runs in the studio process, and the names match the easing asset's. Without a loudness target the old safety stage stays (peaks held at 0.95, now by a deterministic JS limiter instead of `alimiter`).
- **Ducking**: `item.duck = { by (dB), attack, release, hold, source: words|envelope, under: [track ids], threshold }` on the music item. Speech regions come from the narration words (or the RMS envelope of the `under` tracks above a threshold), merged across gaps shorter than `hold`; the gain falls by `by` dB over `attack` *before* each region (the future is known, so it never clips the first syllable) and recovers over `release` after it, on a cosine curve in dB.
- **Loudness**: BS.1770-4 in JS (`src/render/loudness.js`: K-weighting, gated integrated loudness, LRA, 4× oversampled true peak) plans the gain and measures stems and speech regions; FFmpeg `ebur128` on the final MP4 is the number stored with every render. A target (`composition.loudness = { target: -14, truePeak: -1 }`) is met with one fixed gain; only when that gain would push the true peak over the ceiling are the peaks limited first (lookahead limiter, oversampled detection), and the render says so. AAC adds overshoot, so the plan aims 0.5 dB under the ceiling and the final file is measured; if it misses (|I − target| > 0.5 or TP > ceiling) the audio is re-encoded once with the correction and remuxed (`-c:v copy`).
- **Text inspection lives in the standard library**: `f.lib.inspect` (one mutable object per runtime) holds the recorder, a "suppress text" switch and the frame size. `f.lib.text`'s draw functions and `f.lib.solid`'s block-letter meshes report what they draw (text, font, size, colour, box in the context's current transform) to the recorder, and skip drawing when text is suppressed (the frame "without the text" for contrast). The runtime attributes each record to the item being drawn. Recording is off unless asked for, so renders and existing pixels are unchanged. Text drawn with raw `ctx.fillText` is not measured (documented). This is how `check_clip` sees clip 5's REUSE letters: they are 3D block letters used as a mask.
- **Size floors are opt-in per layout call or per asset** (`layout(…, { floor })`, or `asset({ floor })` as the default for its layouts): a percentage of the frame's short side, converted to the context's scale at layout time. `fit` stops at the floor; a block that still overflows, truncates or breaks a word there throws a `TextFloorError` (no ellipsis), so the validator rejects it and the render fails with item, time and text.
- **Latin Extended**: the `@fontsource` latin-ext files are vendored and registered (Node and preview) under an alias family `"<Family> Ext"`, and `fontString` puts that alias right after the family. Skia (and Chrome) pick a font per character down the list, so ă, ș, ț come from the family's own extended file while every Latin glyph still comes from the same file as before (measured: identical pixels and widths for "Hello world", Inter's own ș instead of Segoe UI's). Registering both files under one family name does not work in Skia (it keeps one typeface per family).
